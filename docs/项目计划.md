### P2：GUI 转 Web（前后端分离）

**目标：** 用 Flask + Vue 3 替代 wxPython 桌面 GUI，实现前后端分离架构。

**技术决策：**
- 后端：Flask（Blueprint 分模块，轻量，与现有 handler 结构天然对应）
- 前端：Vue 3 + Vite（学习曲线平缓，对 Python 开发者友好）
- Bokeh 图表维持服务端 components() 渲染，通过 JSON 传 script+div 到前端注入
- 数据库维持 DuckDB（单用户本地，无需多用户隔离）

**分发策略：开源自托管**
- 用户下载代码，用自己的 Tushare token，本地运行
- 不提供统一数据服务，避免 Tushare 限额和数据成本问题
- 将来用户群体成熟后再考虑 SaaS 化（需换 PostgreSQL + 用户系统）

**目录结构目标：**
```
stockanalysis/
├── api/                   ← Flask 后端（原 web_service/ 重构）
│   ├── app.py             ← Flask app 工厂
│   └── routes/            ← chart.py / backtest.py / value.py
└── frontend/              ← Vue 3 + Vite
    ├── src/
    │   ├── views/         ← Chart.vue / Backtest.vue / Value.vue
    │   └── components/    ← BokehChart.vue（封装 script/div 注入）
    └── dist/              ← 构建产物，由 Flask 静态托管
```

## 架构演进方向

```
当前：
  Tushare → pull_tushare(手动) → DuckDB → PyBroker 回测 → Bokeh/GUI
  backtrader_qmt_api (未跑通)

目标：
  Windows 端（核心交易）：
    DuckDB → Backtrader Cerebro
                ├── 回测模式：bt.feeds.PandasData → StrategyAlgo → 绩效分析
                └── 实盘模式：QMTData(live) → StrategyAlgo → QMTBroker → QMT → 模拟盘/实盘

  Mac 端（数据+监控，可选）：
    Tushare → dagster(自动调度) → DuckDB
    Web 看板 ←── REST API ←── Windows 状态
```

## 代码模块对应

| 模块 | 文件 | 说明 |
|------|------|------|
| 回测+实盘引擎 | `engine/engine.py` | Cerebro 封装，支持回测/live 模式切换 |
| 策略执行 | `engine/strategy.py` | StrategyAlgo（基于 bt.Strategy + 算子链） |
| 算子系统 | `engine/algos/` | 时间/选股/权重/再平衡算子（回测/实盘共用） |
| QMT 桥接 | `backtrader_qmt_api/` | QMTStore/QMTBroker/QMTData |
| 数据加载 | `datafeed/dataloader.py` | DuckDB → DataFrame → bt.feeds |
| 绩效分析 | `engine/performance.py` | CAGR/Sharpe/MaxDD 等 |

## 技术决策记录

| 决策 | 选择 | 原因 |
|------|------|------|
| 回测+实盘引擎 | **Backtrader（统一）** | 回测与实盘使用同一套策略代码，live 模式原生支持 |
| 券商接口 | QMT (xtquant) + Backtrader live | A股专用，已有 backtrader_qmt_api 桥接层 |
| 实盘阶段 | 先模拟盘再实盘 | 降低风险，验证流程 |
| 实盘运行环境 | Windows | QMT 客户端仅支持 Windows |
| 跨平台监控 | REST API（可选） | Mac 端 Web 看板监控 Windows 端交易状态 |
| 任务调度 | dagster | 数据管道可视化，适合金融数据场景 |
| GUI 方向 | Flask + Vue 3（前后端分离） | 跨平台；Vue 对 Python 开发者友好；Flask 与现有 handler 结构天然对应 |
| Web 分发策略 | 开源自托管 | 用户自备 Tushare token，避免数据成本；成熟后再 SaaS 化 |
| Web 安装方式 | Docker 优先 + dist/ 预构建 | 降低用户配置 Python/Node 环境的门槛 |
| 数据库 | DuckDB | 分析性能好，单文件部署简单 |
| ~~PyBroker~~ | ~~废弃~~ | 统一到 Backtrader，避免维护两套引擎 |
